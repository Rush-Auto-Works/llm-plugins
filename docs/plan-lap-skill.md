# Plan: Rush SR lap analysis as a Claude plugin skill

## Why

Claude and ChatGPT both skip the lap analyzer when the upload is an AiM `.xrk` file. They see a binary, `pip install libxrk`, and analyze the session themselves, so our tools, UTM link and "Built by Rush Auto Works" card never appear. A converted session is 13 MB or more, so it cannot go through the connector as `csv_text`, and the Free Workers plan allows 10 ms of CPU per request.

Claude's sandbox has Node v22.22.2, pandas and numpy, and reaches PyPI. So the skill runs the same engine there.

```
 .xrk upload ──▶ convert.py (libxrk) ──▶ session.csv ──▶ engine.mjs (node) ──▶ text + UTM card
                 skill script             RaceStudio       the Worker's code,    same words as
                                          layout           bundled               the MCP tool
```

| # | Piece | Files | Owner |
|---|---|---|---|

The three file sets are disjoint. `engine.mjs` (generated by T1) and `convert.py` (T2) share only the directory `plugin/skills/rush-sr-laps/scripts/`.

## Failure matrix

| # | State or input | What happens | How it can fail | What the user is told |
|---|---|---|---|---|
| 1 | `.xrk` with a GPS fix | convert, then analyze | none expected | analysis plus the card |
| 2 | `.xrk` with no GPS Speed channel | convert exits 2 | silent empty CSV | "no GPS Speed channel, the session cannot be analyzed" |
| 3 | `.xrk` with zero laps | convert exits 2 | CSV with no Beacon Markers | "no timed laps in this file" |
| 4 | libxrk missing or PyPI blocked | convert exits 3 with the install command | traceback with no hint | the pinned `pip install` line, and an offer to use a RaceStudio CSV |
| 5 | CSV over the Worker's 1.5 M cell cap | the CLI raises the cap | out-of-memory in the sandbox | an error naming the limit |
| 6 | `node` missing | SKILL.md tells Claude to fall back to the connector with a small CSV | a dead end | one sentence, no stack trace |
| 7 | Binary file passed to the engine | engine rejects it, naming `convert.py` | garbage parsed as CSV | "this is a binary .xrk, run convert.py first" |
| 8 | Unknown command, bad lap number, missing file | exit 1 with the message and the card | a stack trace | the message |
| 9 | Session names from the file | cleaned by the same `clean()` as the Worker | markup or instructions in a driver name | text labelled untrusted, as in the Worker |
| 10 | Engine bundle drifts from the Worker source | CI rebuilds the bundle and fails on a diff; parity E2E compares text | stale `engine.mjs` shipped | CI red |
| 11 | CLI text differs from the MCP tool text | parity E2E compares them with `utm_medium` normalised | two products that disagree | CI red |
| 12 | Bundle over 256 KiB or minified | directory validation holds the plugin for a reviewer | slow listing | CI size check |
| 13 | A converter run on a 17.9 MB `.xrk` | stays under 60 s and 1 GB | timeout in the sandbox | measured before merge |

## Tests first

T1 writes `cli.e2e.test.mjs` red before the CLI exists (rows 5, 7, 8, 9, 10, 11, 12). T2 writes `test_convert.py` against a stub libxrk red before `convert.py` exists (rows 2, 3, 4). Rows 1 and 13 run on the real `.xrk` files in the main loop before the PR is opened.

## Not in this plan

- Two-session comparison (`compare_sessions`), `corner_report` and `list_channels`.
- ChatGPT. Whether a ChatGPT plugin can bundle skills is unverified (task 18).
- License choice and the public repository the directory reads. Both need a decision from Rush.
